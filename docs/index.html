Documentation

Dewpoint 2.0

Dewpoint is an Online Store 2.0 theme for skincare and beauty brands that sell on what is in the bottle. Concerns lead the navigation, every active can carry a published percentage, and the routine is something a visitor can build and add in one go. This page covers installing the theme, every setting and section, the data it reads, and what to do when something does not show.

Getting started

Install

  1. In Shopify admin go to Online Store → Themes. A Theme Store purchase is already in your library. Otherwise choose Add theme → Upload zip file and pick the theme zip.
  2. Click Customize to open the theme editor, or Publish when you are ready. Dewpoint ships one preset, Dewpoint, so there is nothing to choose on install.
  3. The theme contains no photographs. Every image slot without an image renders a typeset placeholder in one of two field tones, so a fresh install looks composed rather than broken. Section text ships as real copy in Dewpoint's voice; replace it with yours.

Sections that need data (the formula ledger, the results band, the routine composer, the concern index) render nothing on the storefront until that data exists, and show a one-line note in the editor saying what is missing. This is by design: a visitor never sees a half-built section.

The ten-minute checklist: concerns and ingredients

Dewpoint is concern-first, so the store reads best once a few collections describe skin concerns rather than product types. This is the shortest path from install to a home page with every section rendering.

  1. Four to seven concern collections. Products → Collections. Give each a one-sentence description and a 4:5 image. Names such as Dehydration, Barrier, Sensitivity. The concern index, the mega menu, the 404 page and the search panel all read them.
  2. A "Concerns" menu. Online Store → Navigation. In the main menu, add an item called Concerns with a nested item called By concern under it, and the concern collections under that. Any item with nested links opens the mega menu; the column whose name contains the word "concern" gets the large list and the image crossfade.
  3. One hero product. On the home page, open the Hero section and pick a product with a 4:5 image. The data caption under the headline builds itself from the product's name, size, actives line and batch.
  4. Routine step names. Theme settings → Routine. The defaults are Cleanse, Treat, Seal, Protect. The collection page's By step list links to collections with those handles (for example /collections/treat), so create them if you want the list.
  5. Free shipping threshold. Theme settings → Cart. Leave it empty to hide the shipping bar.
  6. Ingredients. Either add the ingredient metaobject definition (see Data model) and attach entries to products, or fill the ingredient blocks on the Formula ledger and Ingredient strip sections by hand. Metaobjects are worth it from about three products upward; one entry feeds every section.
  7. The study footnote. If you use the Results band or Results timeline, the footnote is required. Without a stated study, sample size and method, the numbers do not render.

Demo content
The demo pack recreates the demo store: a products CSV with the dewpoint metafield columns, collections, pages, four journal articles, the metaobject definitions and entries, menus and policies. Follow DEMO-STORE-SETUP.md in the pack; it is written for a first store. The pack's photographs are licensed for the demo and are not part of the theme.

Working in the editor

  • Every section has the same first three settings: Color scheme (Field, Tint or Deep), Top spacing and Bottom spacing (Default, Tight or None). Sections whose color is part of the design (Hero, Results band, Results timeline, Footer) do not offer the scheme.
  • Character caps are stated in each setting's help text: hero headline 48, label 40, statement 160, quote 300, step note 120. The theme does not truncate merchant text; the caps keep the type at the size it was designed for.
  • Read order. Wherever the theme can read data it reads the metafield or metaobject first, then a product tag, then the section's own blocks, then hides the element. Blocks are the fallback, not the source of truth.
  • Dynamic sources. Text and image settings accept metafields through the connect icon, as in any Online Store 2.0 theme.
  • Nothing is uppercased or restyled. Merchant strings render as typed. The only uppercase in the theme is its own 12px label layer.

Colors

Five swatches. Tint, slate and raised surfaces derive from Page and Text; the three section schemes (Field, Tint, Deep) derive from all five. A contrast guard checks the pairs on every render: a Page and Text pair, or Deep green against Page, below 4.5:1 falls back to the defaults for that pair, and the editor console says so. If Dew falls below 4.5:1 on Deep green it is replaced by a lighter mix. When muted text drops below 4.6:1 it deepens and the label weight rises to 500.

Accessibility and motion

Reduced motion

Reduced motion is a designed state, not a switch that leaves gaps. It applies when Theme settings → Motion is Reduced, or whenever the visitor's system asks for reduced motion, whichever comes first. Every pattern has a final state that is rendered directly:

PatternUnder reduced motion
Headline line revealThe heading is rendered whole; no split.
Image reveal, block riseFinal state, no transition.
Scroll-driven parallax and ledger fillBars at full width; media static.
Count-up numeralsThe final value is printed at render.
Routine composerUnpinned, flat layout; instant step and tab swaps.
Drawers, mega menu, collapsiblesOpen and close without animation; the spatial state still changes.
VideoStays on its poster; the pause button is the play button.
Page transitions, footer reveal, hero affordanceOff, flat, static.

Headlines are visible before JavaScript runs; the class that hides lines for the reveal is applied in the same frame the animation starts, so there is no flash to invisible. Only transform, opacity and clip-path animate; nothing in the theme moves on a loop except the 40px scroll line under the hero, which is static under reduced motion.

Keyboard and screen readers

  • A Skip to content link is the first focusable element. Every interactive element is at least 44px on primary actions and utilities, and shows a visible focus ring in the deep green.
  • Drawers (menu, bag, quick add, filters) are dialogs: focus is trapped, Escape closes, scroll is locked, and the header does not hide while one is open. The mega menu opens on focus and closes on Escape.
  • Concern index rows are links; focusing a row shows its image. The composer's AM and PM are tabs with arrow-key movement. The before and after comparison is a native range input with a label. The image viewer, the quote controls and the ingredient table's sort buttons are real buttons with state.
  • Cart totals, bag count, added confirmations, form results and the composer counter announce through polite live regions. Toasts are announced once.
  • The ledger bar is an image with a full sentence as its accessible name ("Bakuchiol 1%, Niacinamide 4% …; base and water 89%"), and the label row beneath states the true values.
  • Alt text comes from the media, with the product title as the fallback. Headings run in order on every template; nothing uses a positive tabindex.
  • Without JavaScript: forms post, links navigate, pinned sections lay flat, the search submits to the search page, the composer's Add buttons are plain forms, and the ingredient table reads as authored.

Contrast guard

Every text pair in the default palette clears 4.5:1, including labels on the deep band and the type on placeholder blocks. When you change the five colors, the guard in css-variables.liquid measures the pairs on every render: a failing Page and Text pair, or Deep green against Page, reverts to the defaults for that pair and logs a warning in the editor; a failing Dew is replaced by a lighter mix; muted text below 4.6:1 deepens and the label weight rises to 500. Sale prices, errors and sold-out states use Signal and never color alone.

Performance

  • The priority image. The first image of the first section on a page (the hero, a collection banner, or a product strip with First section on the page turned on; on product pages the first gallery image) loads eagerly with high priority and is preloaded from the layout. It is never lazy, never animated, and never covered by a reveal. Keep it at 4:5 or 21:9 and let the theme size it.
  • Everything else is lazy, responsive (srcset with widths from 300 to 2400) and boxed by an aspect ratio so nothing shifts as it loads. Fonts are preloaded with font-display: swap.
  • Video governance. Only Shopify-hosted video, up to eight seconds and 3 MB, no sound. The poster is the image the page loads; the video uses preload none, starts only when in view, pauses out of view and under reduced motion, and never sits above the fold.
  • JavaScript. Four deferred files and no frameworks: global.js (25 KB unminified) and motion.js (8 KB) on every page; product.js (19 KB) only on product templates; facets.js (9 KB) only on collection and search. One stylesheet, base.css, at 46 KB. Custom elements, the Section Rendering API for the cart, variants, filters, search, paging and recommendations, and nothing loaded from a third party.
  • Motion cost. One IntersectionObserver per pattern; will-change is set immediately before an animation and removed after it; scroll-driven effects use the browser's animation timeline where it exists and a small fallback where it does not.
  • Targets the theme is built against, on a mobile Lighthouse run of the demo home, collection and product pages: performance 75 or higher, accessibility 95 or higher, largest contentful paint on the hero image within 2.5 seconds, layout shift under 0.05. Your own scores depend on your images, apps and hosting; run Lighthouse on your store before launch.

Troubleshooting

A section shows a note in the editor but nothing on the storefront
That is by design. The note says what the section needs (a collection, two steps, a footnote). Add it and the section appears.
The formula ledger is empty
The product has no dewpoint.ingredients metafield and the section has no ingredient blocks. On a product page, also make sure the section's Product setting is empty so it reads the current product. If the percentages add up to more than 100 the editor says so and the bar stays hidden.
The results band or timeline does not show
The study footnote is required. Fill it with the study, sample size and method.
The routine composer lays flat instead of pinning
It needs two or more steps with products, a screen 1024px or wider, motion allowed, and a steps column shorter than the screen. Any one of those missing makes it flat, on purpose.
A menu link to the composer does not land on it
Type the link as /#routine. The section renders with that id.
Filters do not appear on collection pages
Install Shopify's Search and Discovery app and turn on at least one filter. The rail hides filters when there are none.
The By step list links to pages that do not exist
It links to collections whose handles match the step names in Theme settings → Routine (/collections/treat). Create those collections, rename the steps, or turn the list off.
The footer batch lookup goes to a missing page
It posts to the page with the handle batch. Create that page on the Batch page template.
An ingredient page shows the editor note
The ingredient metaobject's handle must match the page's handle, or the page needs dewpoint page metafields, or the section's fields must be filled.
Ratings do not show on cards or the product page
They read the standard reviews.rating and reviews.rating_count metafields that reviews apps write. Turn on Show ratings on cards after the app is writing them.
My colors went back to the defaults
The contrast guard did that: the pair you chose fell below 4.5:1. Pick a darker text or a lighter page, or a deep green that reads on the page color. The editor console names the pair.
The hero shows the statement layout
No image was found: pick a product with an image, or add an image to the Object block. The statement layout is the intended no-image state, not an error.
The header is not transparent
Only the first section decides. The Hero allows it; other first sections do not.
Variant options are a select, not swatches
Swatches appear for options named Color, Colour, Shade or Tint. Up to five values of other options show as a text row; more show as a select.
A gallery image should be wide
End its alt text with [wide]. The marker is removed from the alt text that visitors hear.
Pickup availability is missing
Enable local pickup for a location under Settings → Shipping and delivery, and make sure the variant has stock at that location.
The mega menu does not open
The menu item needs nested links: second-level items become columns, third-level items the links. Name one column with the word "concern" for the large list and the image crossfade.
The store says "Opening on the first of the month"
Password protection is on. Turn it off under Online Store → Preferences, or change the heading in the Password page section.
Texture or How to use shows the wrong product's copy
Those sections are settings on the template. Give each product with its own copy its own template, or keep the sections off the default template.
